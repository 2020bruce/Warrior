# 魂类战斗

在魂类项目中做战斗决策和实现时使用本 Skill。涉及引擎细节时，继续加载 GAS、角色移动、输入、动画、AI 或 C++ Skill。

## 必要手感

- 输入必须在明确且较短的窗口内缓存。
- 每个攻击都定义起手、判定、后摇、取消和无敌窗口。
- 翻滚无敌帧、体力消耗、后摇和方向必须是显式数据。
- 敌人攻击必须可读，并具有明确的追踪上限。
- 削韧和受击反应必须确定、可调。
- 命中停顿、镜头反馈、VFX 和音频必须强化同一套时序。
- 锁定必须稳定，支持切换目标，并正确处理镜头碰撞。
- 死亡、检查点、资源恢复和重试时间必须足够快，保持战斗节奏。

## 数据规则

- 时序以帧数或秒数存储在 DataAsset、曲线或表格中。
- 避免在 Tick 或 Blueprint 图中重复出现无法解释的魔法数字。
- 每个攻击都明确伤害类型、格挡交互、弹反交互、霸体和打断策略。
- 考虑多人前先定义权威和预测方案。

## 实现边界

- 高层动作状态属于战斗组件或能力层。
- 动画通知负责承接命中和无敌窗口。
- 加入多人后，伤害应用由服务器权威决定。
- AI 只负责选择动作，不拥有逐帧战斗真值。

## 验收操作契约

战斗功能改变玩家操作时，必须给 Studio 提供可验收的真实键位：

```json
{
  "version": 1,
  "controls": [
    {
      "action": "轻攻击连段",
      "keyboard": "鼠标左键",
      "gamepad": "RT / 右扳机",
      "notes": "在连段窗口内再次按下可追加下一段"
    }
  ],
  "verification": [
    {
      "label": "按下鼠标左键或 RT",
      "expected": "HUD 显示第 1 段并出现可见攻击动作",
      "required": true
    },
    {
      "label": "面向近距离训练目标完成四段命中",
      "expected": "目标生命从 180 降到 86，伤害为 18/20/24/32",
      "required": true
    }
  ]
}
```

键位必须从 InputAction、InputMappingContext 或运行时代码绑定中确认。任务提示会指定 `acceptance.json` 的绝对路径。`verification` 必须描述用户按什么、看到什么、数值如何变化，不能只写“功能正常”。若任务没有新增或修改操作，也要写入空 `controls` 数组。

## 验证

至少测试一次普通命中、格挡命中、成功翻滚穿过攻击、失败翻滚、体力耗尽、削韧破防和敌人死亡。记录时序和日志证据。在项目目标帧率下测试战斗，并检查镜头与动画过渡。涉及玩家输入时，自动化必须经过 Enhanced Input 或 PlayerController 输入链，不能直接调用最终攻击函数来冒充输入验证。
